### 2. Optimizations You Can Easily Apply (Ordered by Effort vs. Impact)

#### A. Load the Rigged GLB Client-Side for Zero-Latency Pose & Expression Scrubbing (Easy)

Notice that the viewer already has an `/api/export/glb` endpoint (`exportCurrentModel()`, line 614) that exports a rigged GLB.

* **How to apply:** Instead of fetching raw vertex arrays from `/api/geometry` and `/api/deform` on every slider tweak, load the exported `.glb` once using `GLTFLoader` into a true `THREE.SkinnedMesh`, and fetch the linear parameter mapping matrix $T_p$ ($889 \times 204$ floats, ~725 KB) as part of `/api/metadata`.


* **What changes in `app.js`:** Move the deformation call from `elements.slider.addEventListener("change", ...)` to the `"input"` event. Multiply the 204-element parameter vector $\Theta_p$ by $T_p$ in JS to update the 127 `THREE.Bone` local matrices, and set `mesh.morphTargetInfluences` directly for the 45 identity and 72 FACS expression shapes.


* **Effect:**
* **Network traffic drops to zero** after initial load (saving ~221 KB per frame at LOD 1 or ~883 KB per frame at LOD 0).


* **UI locking (`setInputsDisabled`) is eliminated**—sliders scrub smoothly at 60–120 FPS during drag instead of waiting for mouse-up.


* **Main-thread CPU spikes vanish** because GPU skinning transforms both positions and normals on the hardware without calling `computeVertexNormals()` on the CPU.





#### B. Switch to `WebGPURenderer` + Storage Buffers for All 117 Blendshapes + Pose Correctives (Medium)

Standard WebGL limits the number of active morph target textures/attributes, which can become a bottleneck when combining 45 identity shapes, 72 FACS expressions, and sparse pose correctives simultaneously.

* **How to apply:** Swap `THREE.WebGLRenderer` for `THREE.WebGPURenderer` (from `three/webgpu`) and use Three.js Shading Language (`TSL`) storage buffers (`storage()`).


* **How it works:** Store the unposed template $\overline{X}$, the sparse/masked identity and expression deltas ($\mathcal{S}, \mathcal{F}$), and the pose corrective matrices ($P_j$ and masks $\phi(A_j)$) in GPU `StorageBufferAttribute`s. Run a lightweight WebGPU compute shader (`renderer.compute(computeDeformNode)`) whenever a parameter changes to evaluate Equation 2:



$$\tilde{X}(\beta^s, \beta^f, \theta) = \overline{X} + \mathcal{B}^s(\beta^s, \mathcal{S}) + \mathcal{B}^f(\beta^f, \mathcal{F}) + \mathcal{B}^p(\theta, \mathcal{P})$$



right before the standard vertex skinning pass.


* **Effect:**
* Supports **unlimited simultaneous blendshapes and pose correctives** at LOD 0 (73,639 vertices with 8 bone influences per vertex) without hitting WebGL texture-array or vertex-attribute limits.


* Evaluates the entire unposed template deformation + non-linear pose correctives in **less than 0.2 ms** on the GPU, compared to the multi-millisecond server round-trip (`X-MHR-Inference-Ms` + HTTP overhead).

To move the MHR pipeline off the Python server and onto the client GPU using Three.js (`three/webgpu` and `three/tsl`), you split the mathematical formulation of MHR (Equations 1–5) across two ultra-fast stages:

1. **Lightweight CPU Pre-Pass (< 0.1 ms):** Multiply the 204 parameters ($\Theta_p$) by the linear mapping matrix $T_p$ to update the 127 `THREE.Bone` transforms, and evaluate the tiny per-joint MLPs (Equation 4) to get the compact $c$-dimensional pose corrective embeddings ($E_j = \text{Non-Linear}_j(\theta)$).


2. **WebGPU TSL Compute Shader (< 0.2 ms):** Run a single compute pass per vertex (`instanceIndex`) that evaluates Equation 2 and Equation 5—summing the neutral template $\overline{X}$, the 45 identity blendshapes $\mathcal{B}^s$, the 72 FACS expressions $\mathcal{B}^f$, and the sparse pose correctives $\mathcal{B}^p = \phi(A_j) \odot (P_j \times E_j)$—writing directly into the `SkinnedMesh`'s base `position` storage buffer before Three.js's hardware skinning pass runs.



### 1. Memory Layout & Sparse Pose Corrective Packing

At LOD 1 ($V = 18,439$ vertices), storing dense matrices for all 127 joints would waste VRAM. However, because MHR enforces geodesic L1 sparsity via the ReLU mask $\phi(A_j)$ (Figure 7), any given vertex $i$ is only affected by a small handful of nearby joints (typically $K \le 4$).

* **Blendshapes ($\mathcal{S} + \mathcal{F}$):** $N_{bs} = 45 \text{ (identity)} + 72 \text{ (FACS)} = 117$ shapes. Stored as a flat `vec4` buffer of size $V \times 117$ (~34 MB at LOD 1, or ~8 MB if quantized to `Float16`).


* **Sparse Pose Correctives ($P_j$ and $\phi(A_j)$):** For each vertex $i$, store up to $K=4$ active corrective joints in a `uvec4` (`corrJointIds`), their pre-computed ReLU masks $\phi(A_{j,i})$ in a `vec4` (`corrMasks`), and the corresponding rows of $P_j$ in a flat buffer (`corrWeights`).



### 2. Complete Three.js WebGPU + TSL Implementation

```javascript
import * as THREE from "three/webgpu";
import {
  Fn,
  storage,
  instanceIndex,
  Loop,
  uint,
  int,
  float,
  vec3,
  vec4,
} from "three/tsl";

export async function createMHRWebGPUSystem(canvas, mhrData) {
  // 1. Initialize WebGPURenderer
  const renderer = new THREE.WebGPURenderer({
    canvas,
    antialias: true,
    powerPreference: "high-performance",
  });
  await renderer.init();

  const V = mhrData.vertexCount; // e.g., 18439 for LOD 1
  const NUM_BLENDSHAPES = 117;   // 45 Identity + 72 FACS Expressions
  const EMBED_DIM = mhrData.c;   // MLP output embedding size 'c' per joint
  const MAX_CORR_JOINTS = 4;     // Max active sparse corrective joints per vertex

  // 2. Create GPU Storage Buffers for Equation 2 & Equation 5
  // Neutral template vertices \overline{X} (padded to vec4 for 16-byte WGSL alignment)
  const neutralAttr = new THREE.StorageBufferAttribute(mhrData.neutralVerticesVec4, 4);
  const neutralStorage = storage(neutralAttr, "vec4", V).toReadOnly();

  // Combined Identity (S) + Expression (F) deltas: [V * 117] vec4s
  const bsDeltasAttr = new THREE.StorageBufferAttribute(mhrData.blendshapeDeltasVec4, 4);
  const bsDeltasStorage = storage(bsDeltasAttr, "vec4", V * NUM_BLENDSHAPES).toReadOnly();

  // Active blendshape weights (\beta^s concat \beta^f): [117] floats (updated per frame)
  const bsWeightsAttr = new THREE.StorageBufferAttribute(new Float32Array(NUM_BLENDSHAPES), 1);
  const bsWeightsStorage = storage(bsWeightsAttr, "float", NUM_BLENDSHAPES).toReadOnly();

  // Sparse Pose Corrective Lookups per vertex:
  // corrJoints: uvec4 of up to 4 joint indices affecting vertex i
  // corrMasks:  vec4 of \phi(A_j)_i geodesic ReLU masks for those 4 joints
  const corrJointsAttr = new THREE.StorageBufferAttribute(mhrData.corrJointIdsU32, 4);
  const corrJointsStorage = storage(corrJointsAttr, "uvec4", V).toReadOnly();

  const corrMasksAttr = new THREE.StorageBufferAttribute(mhrData.corrMasksVec4, 4);
  const corrMasksStorage = storage(corrMasksAttr, "vec4", V).toReadOnly();

  // Sparse Pose Corrective Weights P_j: [V * MAX_CORR_JOINTS * EMBED_DIM] vec4s (xyz = delta)
  const corrPAttr = new THREE.StorageBufferAttribute(
    mhrData.sparsePMatrixVec4,
    4
  );
  const corrPStorage = storage(
    corrPAttr,
    "vec4",
    V * MAX_CORR_JOINTS * EMBED_DIM
  ).toReadOnly();

  // Per-frame MLP output embeddings Non-Linear_j(\theta): [127 * EMBED_DIM] floats
  const mlpEmbeddingsAttr = new THREE.StorageBufferAttribute(
    new Float32Array(127 * EMBED_DIM),
    1
  );
  const mlpEmbeddingsStorage = storage(
    mlpEmbeddingsAttr,
    "float",
    127 * EMBED_DIM
  ).toReadOnly();

  // Output unposed deformed vertices \tilde{X}(\beta^s, \beta^f, \theta)
  // Using StorageBufferAttribute allows compute shader writes AND vertex shader attribute reads
  const deformedPositionAttr = new THREE.StorageBufferAttribute(
    new Float32Array(V * 3),
    3
  );
  const deformedPositionStorage = storage(deformedPositionAttr, "vec3", V);

  // 3. Author the TSL Compute Shader (Evaluates Eq. 2 & Eq. 5 per vertex)
  const computeUnposedDeform = Fn(() => {
    const vIdx = instanceIndex; // 0 .. V - 1

    // Start with neutral template \overline{X}
    const pos = vec3(neutralStorage.element(vIdx).xyz).toVar();

    // --- A. Identity (\mathcal{B}^s) + Facial Expressions (\mathcal{B}^f) ---
    const bsBaseOffset = vIdx.mul(uint(NUM_BLENDSHAPES));
    Loop(NUM_BLENDSHAPES, ({ i }) => {
      const w = bsWeightsStorage.element(i);
      const delta = bsDeltasStorage.element(bsBaseOffset.add(uint(i))).xyz;
      pos.addAssign(delta.mul(w));
    });

    // --- B. Sparse Non-Linear Pose Correctives (\mathcal{B}^p) ---
    // \mathcal{B}_j^p = \phi(A_j) \odot (P_j \times Non-Linear_j(\theta))
    const jointIds = corrJointsStorage.element(vIdx);
    const masks = corrMasksStorage.element(vIdx);

    Loop(MAX_CORR_JOINTS, ({ i }) => {
      const maskVal = masks.element(i);
      const jointId = jointIds.element(i);

      const pBase = vIdx
        .mul(uint(MAX_CORR_JOINTS * EMBED_DIM))
        .add(uint(i).mul(uint(EMBED_DIM)));
      const embBase = jointId.mul(uint(EMBED_DIM));

      const jointDelta = vec3(0.0).toVar();
      Loop(EMBED_DIM, ({ k }) => {
        const embVal = mlpEmbeddingsStorage.element(embBase.add(uint(k)));
        const pVec = corrPStorage.element(pBase.add(uint(k))).xyz;
        jointDelta.addAssign(pVec.mul(embVal));
      });

      // Apply geodesic ReLU mask \phi(A_j)
      pos.addAssign(jointDelta.mul(maskVal));
    });

    // Write final unposed position \tilde{X} to vertex buffer
    deformedPositionStorage.element(vIdx).assign(pos);
  })().compute(V);

  // 4. Build the SkinnedMesh using Three.js Native Hardware Skinning (Eq. 1)
  const geometry = new THREE.BufferGeometry();
  geometry.setIndex(new THREE.BufferAttribute(mhrData.indices, 1));
  // Bind the compute shader's output storage buffer directly as the mesh's 'position' attribute!
  geometry.setAttribute("position", deformedPositionAttr);
  geometry.setAttribute("normal", new THREE.BufferAttribute(mhrData.normals, 3));
  geometry.setAttribute("uv", new THREE.BufferAttribute(mhrData.uvs, 2));
  // LOD 1-6 strictly use 4 joint influences per vertex
  geometry.setAttribute("skinIndex", new THREE.BufferAttribute(mhrData.skinIndices, 4));
  geometry.setAttribute("skinWeight", new THREE.BufferAttribute(mhrData.skinWeights, 4));

  const material = new THREE.MeshStandardNodeMaterial({
    roughness: 0.55,
    metalness: 0.02,
  });

  const skinnedMesh = new THREE.SkinnedMesh(geometry, material);
  const skeleton = buildMHRSkeleton(mhrData); // Creates the 127 THREE.Bone hierarchy
  skinnedMesh.add(skeleton.bones[0]);
  skinnedMesh.bind(skeleton);

  // 5. Fast Per-Frame / Per-Slider Update Function
  function updateMHRParameters(thetaP204, identityBeta45, expressionBeta72) {
    // Step A: Update 117 Blendshape weights buffer (450 bytes upload)
    bsWeightsAttr.array.set(identityBeta45, 0);
    bsWeightsAttr.array.set(expressionBeta72, 45);
    bsWeightsAttr.needsUpdate = true;

    // Step B: Linear Parameter Mapping (\Theta_j = T_p * \Theta_p) on CPU
    // Maps 204 parameters -> 127 * 7 (889) joint TRS parameters & updates THREE.Bones
    const jointRotations6D = evaluateTpAndBones(thetaP204, mhrData, skeleton);

    // Step C: Evaluate lightweight local joint MLPs (Eq. 4) on CPU (or ONNX Web)
    // Outputs [127 * EMBED_DIM] floats (~2-8 KB upload)
    evaluateLocalPoseMLPs(jointRotations6D, mhrData.mlpWeights, mlpEmbeddingsAttr.array);
    mlpEmbeddingsAttr.needsUpdate = true;

    // Step D: Dispatch WebGPU Compute Pass to update \tilde{X} on GPU
    renderer.compute(computeUnposedDeform);
  }

  return { renderer, skinnedMesh, updateMHRParameters };
}

```

### 3. Implementing the CPU Rig Mapping ($\Theta_j = T_p * \Theta_p$ and Eq. 3)

Because MHR's 127-joint skeleton uses fixed pre-rotations ($T_{prerot}$) and parent offsets ($T_{off}$), the cleanest way to avoid gimbal or hierarchy mismatches in Three.js is to disable `bone.matrixAutoUpdate` and compose Equation 3 directly after multiplying $T_p * \Theta_p$:

```javascript
const _tOff = new THREE.Matrix4();
const _tTrans = new THREE.Matrix4();
const _tPreRot = new THREE.Matrix4();
const _tRot = new THREE.Matrix4();
const _euler = new THREE.Euler(0, 0, 0, "ZYX");

function evaluateTpAndBones(thetaP204, mhrData, skeleton) {
  const { TpMatrix, jointOffsets, jointPreRotations } = mhrData;
  const thetaJ = new Float32Array(127 * 7); // [tx, ty, tz, rx, ry, rz, s] per joint

  // 1. Sparse or dense matrix-vector multiply: \Theta_j = T_p * \Theta_p (889 x 204)
  for (let row = 0; row < 889; row++) {
    let sum = 0;
    const rowOffset = row * 204;
    for (let col = 0; col < 204; col++) {
      sum += TpMatrix[rowOffset + col] * thetaP204[col];
    }
    thetaJ[row] = sum;
  }

  // 2. Compose Equation 3 per joint: T_local = T_off * T_t * T_prerot * T_rot * T_s
  const jointRotations6D = new Float32Array(127 * 6);

  for (let j = 0; j < 127; j++) {
    const base = j * 7;
    const tx = thetaJ[base + 0], ty = thetaJ[base + 1], tz = thetaJ[base + 2];
    const rx = thetaJ[base + 3], ry = thetaJ[base + 4], rz = thetaJ[base + 5];
    const scale = 2.0 ** thetaJ[base + 6]; // Exponential uniform scale (only hand scale params drive this channel)

    _tOff.makeTranslation(
      jointOffsets[j * 3 + 0],
      jointOffsets[j * 3 + 1],
      jointOffsets[j * 3 + 2]
    );
    _tTrans.makeTranslation(tx, ty, tz);
    _tPreRot.makeRotationFromQuaternion(
      new THREE.Quaternion().fromArray(jointPreRotations, j * 4)
    );

    // MHR composes R = Rz * Ry * Rx, i.e. THREE Euler order "ZYX"
    _euler.set(rx, ry, rz, "ZYX");
    _tRot.makeRotationFromEuler(_euler);

    // Superseded sketch for the fictional Eq. 4 (see header note): the released MLP consumes rows of Rx*Ry*Rz instead.
    const e = _tRot.elements;
    const r6Base = j * 6;
    jointRotations6D[r6Base + 0] = e[0] - 1.0;
    jointRotations6D[r6Base + 1] = e[1];
    jointRotations6D[r6Base + 2] = e[2];
    jointRotations6D[r6Base + 3] = e[4];
    jointRotations6D[r6Base + 4] = e[5] - 1.0;
    jointRotations6D[r6Base + 5] = e[6];

    // Apply uniform scale T_s and compose into bone.matrix
    _tRot.scale(new THREE.Vector3(scale, scale, scale));

    const bone = skeleton.bones[j];
    bone.matrixAutoUpdate = false;
    bone.matrix
      .copy(_tOff)
      .multiply(_tTrans)
      .multiply(_tPreRot)
      .multiply(_tRot);
    bone.matrixWorldNeedsUpdate = true;
  }

  return jointRotations6D;
}

```

### Why This Architecture Excels in `WebGPURenderer`

* **PCIe Bandwidth Drops by 99.5%:** Instead of downloading ~221 KB of posed vertices from Python and uploading them to the GPU on every slider change (as `app.js` currently does), you only upload **468 bytes** of blendshape weights (`117 * 4` bytes), **~4 KB** of MLP embeddings (`127 * c * 4` bytes), and **8 KB** of bone matrices (`127 * 16 * 4` bytes).


* **Zero-Copy Compute-to-Vertex Handoff:** Because `deformedPositionAttr` is a `THREE.StorageBufferAttribute` bound both to the TSL `computeUnposedDeform` shader and to `geometry.setAttribute("position", deformedPositionAttr)`, the unposed deformed template $\tilde{X}$ never leaves GPU VRAM before Three.js's built-in `SkinnedMesh` vertex shader applies the 4-bone Linear Blend Skinning pass.


* **Instant Clothing Support:** If you attach a garment `SkinnedMesh` that shares the exact same `skeleton` instance, the garment automatically inherits the bone length scaling ($\beta^k$), twist-bone distributions, and pose rotations without needing a separate rig update.
